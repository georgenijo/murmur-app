## Purpose & Scope

This document establishes the authoritative feature and ownership matrix for Murmur's rewrite from Tauri 2 (Rust + React + WebKit) to native GPUI. As mandated by Plan §1.0 and issue #984, this matrix defines the acceptance criteria and exit gates for every subsequent phase of the rewrite.

Every user-facing behavior in Murmur is cataloged with its owning module after Phase 1 core extraction, the exact phase and migration step that ports it, prerequisites, an unambiguous native acceptance flow, existing verified tests, and the replacement GPUI test suite.

## Migration Route & Stack Execution Order

The Phase 0 exit decision (`docs/decisions/2026-11-05-gpui-phase-0-exit.md`) firmly established the **Native Parity First** route. Under this route:

1. **Phase 1: Core Extraction (1.0–1.8, minus 1.7)**. Headless extraction of dictation control, completion service, state ownership, updater, and shutdown coordinator into a pure Rust core (`murmur_core`). Shipped and verified in the current Tauri app.
2. **Phase 3: Screen Ports (3.1–3.5e)**. All native windows and screens are developed beside the shipping app using GPUI components ported to the pinned Zed revision `654efae441bc8eb117d0042bb28cd7cf3570bdc9`. Screens port section by section (History, Settings, Onboarding/Home, Meetings, remaining sections) until 100% native parity is achieved.
3. **Phase 2: Host Replacements & Packaging (2.1, 2.3, 2.4)**. Non-Tauri packaging, native AppKit host replacements (`NSStatusItem`, GPUI menus, `SMAppService`, `UNUserNotificationCenter`, `NSOpenPanel`), code-signing rehearsals, and TCC permission-continuity checks.
4. **Phase 4: Removal (4.0)**. Clean deletion of WebKit, Tauri, React, Node tooling, and bridge dependencies.

### Dropped Items & Absorbing Steps

Because Murmur follows the Native Parity First route and will not ship a hybrid webview/GPUI binary to users, hybrid bridge machinery designed solely for intermediate releases is dropped:

- **0c (#981, Embed GPUI in Tauri)** and **0d (#982, React inside GPUI window)**: Dropped at Phase 0 exit. Absorbed by the native parity first development flow.
- **1.7 (#991, Frontend host adapter)**: Dropped. In native parity first, React screens do not need an abstract Tauri plugin wrapper. Phase 3 GPUI screens interact directly with the Rust core, and Phase 2 Step 2.3 (#996) provides native host replacements.
- **1.9 (#993, Lazy Tauri diagnostics window)**: Dropped. The Tauri diagnostics window configuration remains unchanged. Absorbed by Phase 3 Step 3.4 (#1001), where the native GPUI diagnostics window is created lazily on first user open.
- **2.2 (#995, Bridge for unported React screens)**: Dropped. No wry webviews are hosted inside GPUI windows. Absorbed by Phase 3, which ports all screens to native GPUI before the host flip.

## Invariants Preserved Across All Phases

Every row in this matrix strictly preserves the core invariants defined in `docs/draft/gpui-rewrite-plan.md`:

- **Immutable Recording Snapshots**: Dictation configuration is resolved once at recording start. Every asynchronous continuation rechecks the generation counter before mutating shared state; only the owning generation can be stopped or cancelled.
- **Exactly-Once Publication & History/Stats Accounting**: Every completed utterance produces exactly one transcript delivery, exactly one History entry (unless `retainHistory=false`), and exactly one statistics journal event. File transcriptions create History entries without statistics.
- **Rust Native Window Ownership**: Window frames, placements, and levels are computed exclusively by Rust. Core logic off the main thread reaches windows strictly through a main-thread dispatcher.
- **Single Keyboard Listener**: rdev runs on exactly one background thread initialized with `set_is_main_thread(false)`.
- **Privacy Bounds**: No transcript, audio, clipboard, or selection text is ever emitted to logs, telemetry, bridge traces, or test goldens.
- **Durable Storage & WebKit Retirement**: User data lives in Rust-owned atomic files or SQLite stores with `F_FULLFSYNC`. No user state lives solely in WebKit `localStorage`.
- **Shutdown Integrity**: The shutdown coordinator intercepts all quit signals (⌘Q, Dock Quit, Menu Quit, logout, restart), draining in-flight meeting capture for up to 5s and flushing durable state before process exit.

## Matrix Specification

The matrix is organized into functional feature areas. Each entry contains:
1. **Behavior**: The distinct user-facing feature or interaction.
2. **Owning Module (Post-Phase 1)**: The authoritative Rust core module or UI host module.
3. **Move Step & Phase**: The stack migration step, phase, and GitHub issue number.
4. **Prerequisites**: Dependent core abstractions or prior screen milestones.
5. **Native Acceptance Flow**: Concrete clicks, keystrokes, and verifiable user outcomes.
6. **Existing Tests**: Verified test file paths currently existing in the repository.
7. **GPUI Replacement Tests**: Concrete replacement test files in the GPUI target test suite.
