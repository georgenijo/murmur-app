# Shawn Microphone Initialization Diagnosis

**Diagnosis (2026-08-03; high confidence, based on production telemetry and source review):** Shawn's M5 MacBook Air is not failing because Murmur cannot enumerate a microphone, lacks permission, or cannot launch its signed capture worker: on v0.24.2 the uploaded state reports successful enumeration with a default input and three available inputs, and each failed recording successfully launches the worker, completes its protocol handshake, sends an AUHAL start request, and enters `StreamOpen`. The worker then emits neither `AwaitingFirstCallback` nor first PCM, which localizes the hang to the synchronous AUHAL open/configure/start sequence (`start_auhal`) before callback waiting begins, although the current telemetry cannot identify the exact CoreAudio/AudioUnit call inside that sequence. After 30 seconds the outer audio lifecycle declares `initialization_timeout` and sends `Stop`; the host's backend runner treats that cancellation as `AttemptResult::Stopped`, so the AUHAL-to-CPAL loop exits instead of converting the hung primary attempt into a fallback-eligible failure. Production evidence supports this control-flow diagnosis: v0.24.2 recorded six attempts with zero readiness events, four hard-deadline failures, and two user cancellations, with no CPAL fallback event; v0.24.1 likewise recorded zero ready attempts and no CPAL fallback. Thus CPAL 0.18 is present but is never exercised for this specific failure class, contrary to the intended bounded pre-recording failover contract in issue #412. A likely corrective design is to enforce a per-backend pre-first-buffer deadline inside the backend runner, hard-kill and confirm exit of a hung AUHAL helper, return a fallback-eligible timeout, and then try CPAL against the exact same physical device within the overall lifecycle budget; a deterministic test should cover a primary backend that never returns and an alternate backend that succeeds. Separately, microphone-state enumeration should be suppressed while capture initialization owns the HAL boundary, because the log shipper currently can launch an additional enumeration helper during a stuck attempt; this does not explain the initial hang, but it introduces avoidable concurrent HAL activity. This diagnosis explains the observed behavior and the missing fallback, but the precise macOS call that hangs still requires finer-grained worker telemetry or reproduction on Shawn's machine.
