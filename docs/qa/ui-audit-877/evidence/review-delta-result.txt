## Remaining finding — severity ranked

### P2 — Reset can remove the theme editor’s recorded opener, leaving focus on the document body

**Candidate location:** `app/src/components/settings/AppearanceSettings.tsx:351` — the new explicit `restoreFocus={() => editorOpenerRef.current}` callback.

**Failing scenario:**

1. Have a Custom theme active and open the theme editor through **Edit Custom**.
2. Choose **Reset to Sonic** and let the reset finish.
3. Close the editor with **Done**, Escape, or Close.

**Expected:** Restore focus to the actual invoker when it still exists, or to a stable connected fallback such as **Create theme** when Reset has removed that invoker.

**Actual:** Reset changes both theme selections to `sonic` (`app/src/lib/hooks/useAppearance.ts:323–328`). The Custom card is conditional on at least one selection being `custom`, so the reset unmounts that card and its **Edit Custom** button (`app/src/components/settings/ThemeLibrary.tsx`, Custom-card conditional). The new explicit restoration callback nevertheless returns the detached button. With `preferExplicitRestore=true`, the unchanged shared `useDialogFocus` selects that non-null explicit destination and calls `.focus()` without testing `isConnected`; focusing the detached element has no effect. Keyboard focus is left on the document body rather than a useful control. This is a remaining defect in the newly added restoration path, not a request to redesign the unchanged hook.

**Verification performed:** Reproduced using the exact candidate `AppearanceSettings`, `ThemeLibrary`, `useDialogFocus`, and default-button sources compiled entirely in memory, React, and JSDOM. The theme controller was mocked to apply the same reset transition verified in the actual candidate hook; theme tokens and unrelated integrations were mocked. The result was:

```json
{
  "candidate": "da53e423e440a1418c7e5e6094ca10ab0342cc71",
  "scenario": "Edit Custom -> Reset to Sonic -> Done",
  "customOpenerDisconnected": true,
  "dialogClosed": true,
  "activeElement": "BODY",
  "activeLabel": null,
  "persistentCreateButtonPresent": true
}
```

This is a component-level reproduction, not a native receipt. The source trace establishes the real reset/removal path. Existing new appearance tests cover **Create theme** and **Create theme from Sonic**, whose buttons persist; they do not exercise the disappearing **Edit Custom** opener.

**Minimal fix:** Test the recorded opener’s `isConnected` state and otherwise return a stable **Create theme** button ref supplied by `ThemeLibrary`, analogous to Voice Commands’ existing New-command fallback. Add a regression opening **Edit Custom**, applying the reset/controller update so its card actually unmounts, and closing the dialog. Preserve live-applied theme semantics. Recheck this narrow delta and its actual native restoration flow; a new full review is unnecessary.
