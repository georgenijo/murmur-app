# Private native capture CI controller

This directory is the source template for the private `georgenijo/murmur-native-ci` repository. The public Murmur repository has no self-hosted runner registration. Only the private controller receives the `murmur-capture-macbook` runner.

The controller accepts `workflow_dispatch` from `georgenijo` on its default branch. Inputs identify an immutable commit and a trusted public Murmur branch containing it. `main` is the automatic source. Owner-reviewed `issue/<number>-<description>` branches support verification before merge. The controller fetches the named branch, proves the commit is its ancestor, and checks out that exact commit.

The job builds the worker with its production role and embedded worker Info.plist, then runs both backends through first PCM and stop. Its token has `contents: read`. It has no cross-repository PAT or publish permission. A local authenticated operator can attach the resulting content-free evidence to the public PR.

The runner account needs Rust 1.96, Apple command-line tools, meson, ninja, pkg-config, Python 3, an open MacBook lid, and microphone permission in the actual job process context. The production Murmur application and its permissions remain separate. After provisioning, verify both backends in the actual Actions runner process context. A successful native CLI invocation alone does not prove that job context.

Automatic triggering is a separate local Fleet controller responsibility. `poll_capture.py` tracks public `main`, compares changed capture paths, and dispatches this workflow with the immutable main SHA through the existing local `gh` authentication. A control-node LaunchAgent can invoke it every five minutes with `--state-dir` pointing to a dedicated local state directory. Keep that schedule disabled until `main` contains the capture probe; otherwise an unrelated main update can dispatch a job whose source lacks the probe. Before that first merge, verify the owner-reviewed candidate through a private manual dispatch. Enable the schedule after merge and observe its first changed-main run. The poller serializes concurrent invocations, suppresses an already-listed SHA run, and advances its state only after successful dispatch or a change outside capture paths. It must never execute pull-request code or read token files. Manual dispatch alone does not satisfy the issue's automatic capture-path CI criterion.

The controller repository must remain private and owner-only, with no outside collaborators or pending invitations. GitHub does not expose the private-fork policy switch for User-owned repositories; `allow_forking` remains true, but forking still requires existing repository access. Adding a collaborator therefore expands the runner trust boundary and requires review. Verify repository access before enabling the runner. Workflow guards supplement that repository boundary. They do not make registration on the public repository safe. A pre-job hook also does not replace repository isolation.
